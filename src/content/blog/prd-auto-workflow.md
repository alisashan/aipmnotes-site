## 痛点

传统 PRD 撰写耗时长：信息散落在会议纪要、脑图、原型备注里，整理格式又要占去半天。

## 工作流设计

1. **输入**：会议录音转写 / 结构化访谈笔记 / Figma 原型链接
2. **结构化**：LLM 提取用户故事、验收标准、非功能需求
3. **生成**：按团队 PRD 模板输出章节（背景、目标、范围、流程、数据、风险）
4. **评审**：人工修改后定稿，版本写入 Git 或文档库

## Prompt 设计要点

- 模板章节固定，减少每次「格式漂移」
- 强制标注「待确认」项，避免模型编造业务规则
- 引用原文片段，方便评审时核对来源

## 效果

试点后，从初稿到可评审文档的时间可缩短约 40%–60%，产品经理把时间集中在逻辑校验与优先级判断上。

## 延伸

与 Hermes Agent 结合，可在需求变更时自动 diff PRD 相关章节，生成变更说明草案。
